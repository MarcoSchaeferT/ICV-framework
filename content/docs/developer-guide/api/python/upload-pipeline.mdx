Stream multipart files into an upload-specific work directory.

`DirectUploadRequest` writes file parts to disk while Flask parses the
request. The route initializes Redis-backed status (or local fallback)
before returning `upload_id` and schedules sequential ingestion in a
worker-local event loop. The HTTP response means processing started, not
that the database write succeeded.
Invalid or unsaved files return an error and remove the work directory.
The client polls `/api/uploadStatus?id=<upload_id>` for completion or a
background error. The work directory is removed after either outcome.

### `uploadFileToDB`

```python
async def uploadFileToDB(file_path: Path, upload_id: str)
```

Ingest one CSV snapshot under a cross-worker filename lock.


**Returns**

`None` on success or a dict containing `error` or `restart`.

Replaces the relation schema, streams row insertion, populates column
metadata, optionally assigns countries with Shapely, and invalidates
relation-scoped cache entries. The file-name processing lock is shared
across workers when Redis is available and released even on failure.
A metadata-population exception is logged and does not stop ingestion;
a country-assignment exception becomes a processing error.
Schema replacement and COPY are separate transactions, so a later error
does not restore the prior table. Cache invalidation runs on success.

### `query_raw`

```python
async def query_raw(query: Union[str, sql.SQL, sql.Composed], params: Optional[Union[tuple, dict]]=None) -> list[dict]
```

Execute a SELECT through a server-side cursor and return dictionaries.

A named cursor prevents libpq from buffering the complete result before
Python starts consuming it.  The returned list intentionally preserves the
existing API contract, while driver fetches use 10,000-row batches. The
final list still contains every returned row,
so callers must bound large results or use `query_columnar`.

`params` binds values; callers compose dynamic table and column names
with `psycopg.sql.Identifier`. Database errors propagate to the caller.

**Parameters**

<TypeTable type={{"query": {"type": "Union[str, sql.SQL, sql.Composed]", "required": true}, "params": {"type": "Optional[Union[tuple, dict]]", "required": false, "default": "None"}}} />

### `query_columnar`

```python
async def query_columnar(query: Union[str, sql.SQL, sql.Composed], column_names: Sequence[str], params: Optional[Union[tuple, dict]]=None, fetch_size: int=10000, row_mapper: Optional[Callable[[tuple], Sequence]]=None) -> dict[str, list]
```

Stream a SELECT into column arrays without per-row dictionaries.

This is the preferred path for large visualization datasets.  It avoids
both `fetchall()` and hundreds of thousands of Python dictionaries while
retaining a compact JSON-friendly result. Each key in `column_names`
receives one value per row, in the supplied order. `row_mapper` may
transform each raw tuple before values are appended. The returned arrays
still grow with the full result set; they are not a bounded page.

### `_resolve_type`

```python
def _resolve_type(counts: dict[str, int]) -> str
```

Given per-type vote counts for a column, decide on the dominant type.

Rules (applied in order):
1. If *every* non-empty value is an integer → `int`
2. If *every* non-empty value is numeric (int or float) → `float`
   (ints are promotable to floats)
3. If ≥ 80 % of non-empty values look like dates → `date`
4. Otherwise → `string`

### `ParsedData`

```python
class ParsedData
```

CSV header and upload metadata shared by schema creation and COPY.

`column_names` preserves source headers; `sanitized_column_names`
aligns by index with them and names the PostgreSQL columns. `file_size`
is measured in bytes for progress reporting. Rows remain on disk.


**Example**

```python
parsed = ParsedData()
parsed.db_name = "dengue_serotype_counts"
parsed.column_names = ["Country", "Year", "Serotype Count"]
parsed.sanitized_column_names = ["country", "year", "serotype_count"]
parsed.file_size = 18432
```
